# SimpleFund

Monorepo with React frontend and FastAPI backend for managing investment funds.

## Structure

```
frontend/   # React + Vite app
backend/    # FastAPI app
```

---

## Frontend

### Stack

- **React** + **TypeScript** + **Vite**
- **Shadcn/ui** + **Tailwind CSS**
- **React Query** — the only way to communicate with the API
- **React Hook Form** + **Zod** — form state management and validation

### Project structure

```
frontend/src/
├── api/           # React Query hooks + fetch functions grouped by resource (funds.ts, portfolio.ts)
├── components/
│   ├── ui/        # auto-generated by "shadcn add" — do not edit manually
│   ├── forms/     # generic reusable form field components (FloatInput, BuySellSelect…)
│   ├── modals/    # modal dialogs with forms
│   └── ...        # custom components built on top of ui/
├── hooks/         # custom hooks unrelated to API: useDebounce, useLocalStorage etc.
├── types/         # TS interfaces shared across the application
├── lib/
│   └── utils.ts   # cn() required by Shadcn/ui
├── pages/         # page components, one file = one route
├── App.tsx        # routing + QueryClientProvider + providers
└── main.tsx       # entry point, React mount
```

### Rules

#### API and React Query

- All backend communication happens **exclusively through React Query** (`useQuery`, `useMutation`)
- Hooks and fetch functions are kept together in `src/api/`, grouped by resource
- Never fetch data directly in a component outside of a hook from `src/api/`

```ts
// src/api/funds.ts
const fetchFunds = async (): Promise<Fund[]> => { ... }

export const useFunds = () => useQuery({ queryKey: ['funds'], queryFn: fetchFunds })
```

#### Colors and styling

- All colors defined **exclusively** as CSS variables in `src/index.css` — never hardcoded in components
- In components use only Tailwind classes that reference those variables (`bg-background`, `text-primary`)
- Spacing and sizes exclusively from the Tailwind scale (`p-4`, `gap-6`) — no arbitrary values (`p-[13px]`)

#### Shadcn/ui

- Components in `src/components/ui/` are auto-generated — **do not edit manually**
- Add new Shadcn components via `shadcn add <component>`
- Build custom components on top of `ui/` components, not from scratch

#### Functions

- Always use **arrow functions** — `const Foo = () => { ... }`, never `function Foo() { ... }`
- Helper functions used only inside a component are declared **inside** that component as `const`

#### Forms

- All forms use **React Hook Form** + **Zod** for state management and validation
- Define the Zod schema in the same file as the form/modal component
- Use `zodResolver` from `@hookform/resolvers/zod` to connect the schema
- Use `Controller` from `react-hook-form` to wrap Shadcn/ui controlled components (Select, Popover, etc.)
- Generic reusable field components live in `src/components/forms/` (e.g. `FloatInput`, `BuySellSelect`)
- Modal components with forms live in `src/components/modals/`
- Always call `reset()` on modal close to clear form state

## Backend

### Stack

- **FastAPI** — web framework
- **Pydantic** — data validation and request/response schemas
- **SQLAlchemy** — ORM
- **Alembic** — database migrations
- **Supabase** — databse, authentication (JWT verification)
- **pytest** — testing
- **uv** — package manager and virtual environment (`uv add`, `uv run`)

### Project structure

```
backend/
├── app/
│   ├── main.py              # FastAPI instance, include_router, middleware
│   ├── config.py            # settings via Pydantic Settings, env variables
│   ├── dependencies.py      # shared dependencies (get_db, get_current_user)
│   │
│   ├── api/
│   │   └── v1/
│   │       ├── router.py    # aggregates all v1 routers
│   │       └── ...          # one file per resource
│   │
│   ├── models/              # SQLAlchemy table models
│   ├── schemas/             # Pydantic schemas (request/response shapes)
│   ├── repositories/        # database queries — one file per table
│   └── services/            # business logic, calls repositories
│
├── alembic/
│   ├── versions/            # generated migration files
│   ├── env.py               # Alembic config (imports models)
│   └── script.py.mako       # template for new migrations
│
├── tests/
├── alembic.ini
├── .env
└── pyproject.toml
```
